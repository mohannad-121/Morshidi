# 00 - Executive Technical Overview
# الملخص التقني التنفيذي لمشروع الربط التجريبي

### 1. الرؤية والهدف
يهدف هذا المشروع لتشغيل بيئة تجريبية آمنة وذكية لمنصة **مرشدي** بالشراكة مع الجامعة لتمكين الطلبة من التخطيط الفصلي الذكي وتزويد إدارات الكليات والتسجيل بمؤشرات استباقية للطلب والاختناقات الأكاديمية، مع الحفاظ الكامل على سيادة وموثوقية نظام معلومات الطلبة (SIS) التابع للجامعة.

### 2. المبادئ الحاكمة للربط
1. **الذكاء يشرح — والقواعد الحتمية تقرر:** لا تتدخل نماذج الذكاء الاصطناعي في إقرار الأهلية أو النجاح أو التخرج؛ المحركات الحتمية هي التي تطبق تعليمات الجامعة بدقة.
2. **نظام الجامعة هو المرجع الرسمي الأول والأخير:** مرشدي لا يحل محل نظام معلومات الطلبة، بل يتكامل معه كطبقة ذكاء وإرشاد متقدمة.
3. **نمط القراءة أولاً (Read-Only First):** تبدأ المرحلة التجريبية بنمط قراءة فقط دون أي تعديل أو كتابة على قاعدة بيانات الجامعة.
4. **العزل التام والخصوصية:** عزل كامل لبيانات الجامعة عبر تقنيات Multi-Tenancy و Row-Level Security، دون جمع أي بيانات مالية أو شخصية غير لازمة.
5. **حظر الاتصال المباشر بقواعد البيانات:** الربط يتم حصرياً عبر واجهات RESTful مشفرة أو تبادل رموز الهوية الموحدة.

# 01 - IT Discovery Questionnaire & Kickoff Checklist
# استبيان الاستكشاف التقني وقائمة الاجتماع الافتتاحي

### أولاً: جدول أعمال وقائمة فحص الاجتماع التقني الأول (Kickoff Checklist)
- [ ] **ملكية النظام (SIS Ownership):** من يدير نظام الـ SIS في الجامعة (فريق داخلي أم شركة مزودة)؟
- [ ] **اسم النظام والإصدار (Vendor & Version):** Banner, PeopleSoft, EduWave, نظام محلي مخصص؟
- [ ] **توفر الواجهات (API Availability):** هل تتوفر واجهات RESTful مع وثائق Swagger/OpenAPI؟
- [ ] **البيئة التجريبية (Sandbox Access):** هل تتوفر بيئة منفصلة للاختبار تحتوي على بيانات وهمية؟
- [ ] **الدخول الموحد (SSO / IdP):** هل يعتمد الطلبة على Microsoft Entra ID / ADFS / Shibboleth / OIDC؟
- [ ] **صيغة المعرف الطلابي (Student Identifier):** ما هو الحقل الممثل للرقم الجامعي في الـ IdP؟
- [ ] **هيكلية الخطط الأكاديمية (Curriculum Versioning):** كيف تُميز الجامعة الخطط القديمة والحديثة؟
- [ ] **سياسة العلامات والمعدل (Grading Policy):** هل النظام مئوي (0-100) أم من 4.0؟ وكيف تُعامل المواد المعادة؟
- [ ] **فترات التسجيل (Registration Windows):** هل يوجد فترات محددة لكل دفعة؟
- [ ] **طاقة الشعب الاستيعابية (Seat Capacity):** هل تتوفر بيانات سعة الشعب والمقاعد المتبقية عبر الـ API؟
- [ ] **إمكانية الويب هوك (Webhooks):** هل يمكن إرسال إشعارات لحظية عند تعديل علامة أو شعبة؟
- [ ] **قيود الشبكة والجدار الناري (Network & Firewall):** ما هي الإجراءات المطلوبة لاعتماد خوادم مرشدي؟
- [ ] **الحسابات التجريبية (Test Student Accounts):** جاهزية 6-10 حسابات طلابية وهمية لسيناريوهات الفحص.
- [ ] **تحديد جهات الاتصال (Named Roles):** تسمية المنسق التقني، المنسق الأكاديمي، ومسؤول الأمن السيبراني.

### ثانياً: استبيان الاستكشاف التقني (Discovery Questionnaire)
1. **بنية الـ SIS:**
   - ما هو اسم المطور/الشركة المسؤولة؟
   - هل الاستضافة في حرم الجامعة (On-Premise) أم سحابية (SaaS)؟
2. **بروتوكولات الأمان:**
   - ما هي طريقة توثيق الـ API (OAuth 2.0 Client Credentials, API Key, Token)؟
   - هل تطلب الجامعة شهادة TLS معينة أو VPN مخصص؟
3. **الدفعة التجريبية المستهدفة (Pilot Cohort Scope):**
   - الكليات المقترحة للمرحلة الأولى: (مثال: كلية تكنولوجيا المعلومات).
   - التخصصات المستهدفة: (مثال: الذكاء الاصطناعي، هندسة البرمجيات).
   - الفصول المستهدفة: (مثال: الفصل الأول 2026/2027).
